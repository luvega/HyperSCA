# HyperSCA-C 第一版方法说明

## 这项方法研究什么

HyperSCA-C 学习这样一类有向候选关系：干预一个基因后，哪些其他基因可能随之改变。它面向任务 C 的单细胞基因干预评测，当前研究对象是 K562 和 RPE1 两种细胞背景中的基因—基因关系。

HyperSCA 原有阶段 2 与 HyperSCA-C 研究的不是同一个对象：

| 项目 | 原有 HyperSCA 阶段 2 | HyperSCA-C |
|---|---|---|
| 每个变量代表什么 | 细胞群 | 基因 |
| 每条观测代表什么 | 基因被作为探索性重复观测 | 单个细胞 |
| 关系的含义 | 细胞群之间的候选通讯关系 | 一个基因指向另一个基因的候选作用关系 |
| 主要用途 | 描述组织微环境中的细胞群联系 | 检查干预后基因变化能否帮助恢复有向关系 |

两类图不能互相替代，也不能把原有细胞群通讯图改换格式后称为基因调控图。HyperSCA-C 的结果同样不是已经证实的调控机制。

## 数据单位、变量和允许使用的范围

每个细胞环境的数据记为 `X_c`。一行是一个细胞，一列是固定顺序中的一个基因，`c` 表示 `k562` 或 `rpe1`。每个细胞还有一个干预标签：基因名表示该基因受到直接干预，`non-targeting` 表示未定向干预对照，`excluded` 表示该行不参加表达误差计算。

正式运行还需要一份有序基因清单。清单必须记录 `selection_id`、选择依据 `selection_basis` 和基因顺序。选择基因时只能查看相应学习阶段允许使用的数据；不得利用最终检验响应、评分参考关系或比较结果倒推基因集合。当前运行入口只核验 2 至 256 个基因。这个范围是本轮软件核验和资源控制边界，不是科学上的最佳基因数，也不表示 256 个基因足以覆盖真实调控网络。

模型只读取公开分析记录清单（manifest）`public_manifest.json` 登记且内容指纹一致的文件。路径含 `private/`、未登记文件、符号链接、内容指纹不符或与公开清单语义不一致时，运行会停止。未参与模型建立的独立验证数据（holdout）保存在 `private/`，不得用于选基因、建立模型、调整参数、选择消融、决定停止时机或修改报告规则。

## 第一版线性关系模型

### 共享关系和细胞环境调整

对细胞环境 `c`，模型写为：

```text
A_c = A_shared + Delta_c
X_c 的预测值 = X_c @ A_c
```

`A_shared` 表示各个已提供细胞环境可共享的关系；`Delta_c` 表示环境特有调整。只提供一个环境时，数据不能把 `A_shared` 和 `Delta_c` 唯一分开，只有两者之和 `A_c` 可以直接解释。矩阵方向固定为 `A_c[source, target]`：行索引是来源基因，列索引是目标基因，因此 `source → target` 对应 `A_c[source, target]`。所有对角元素固定为零，不输出基因指向自身的关系。

环境调整并不是不受限制的自由矩阵。模型分别限制共享关系的总量和环境调整的总量，使关系保持较稀疏，并避免环境调整任意吸收全部差异。不过，这些限制是连续惩罚，不是对真实生物差异大小的硬边界。

### 对照细胞标准化

每个细胞环境独立进行标准化。每个基因的中心和尺度只由该环境的 `non-targeting` 对照细胞估计；标准差使用总体定义 `ddof=0`。若某个基因的对照标准差不大于 `1e-6`，计算时把尺度设为 1，避免除零。干预细胞不参与中心和尺度的估计。

### 如何使用直接干预标签

若某个细胞的基因 `g` 被直接干预，而且 `g` 位于固定基因清单中，模型不计算该细胞中 `g` 自身的表达解释误差。该细胞中其他基因的误差仍保留，用于估计 `g` 可能指向哪些下游基因。这个遮挡规则避免模型把实验操作造成的直接目标变化当成目标基因的正常输入关系。

若干预标签对应的基因不在固定清单中，清单内各基因仍可作为该干预的下游观察量，但模型不会为清单外基因输出关系。`excluded` 行的全部表达误差均被遮挡。

### 拟合目标和无环软限制

模型同时减小四部分：未遮挡表达值的平滑绝对误差、共享关系的稀疏限制、环境调整的稀疏限制，以及 NOTEARS 形式的无环软限制：

```text
h(A_c) = trace(exp(A_c * A_c)) - p
```

这里的 `*` 是逐元素相乘，`p` 是基因数。该项只是在拟合时对循环关系增加代价，并不强制最终矩阵严格无环，更不表示真实基因网络没有反馈。第一版只采用线性关系，便于逐项检查假设、数值失败和消融结果；非线性调控、时间延迟和反馈动力学不属于本版范围。

## 重复抽样、完整输出和固定分数

模型在每一种干预标签内部进行有放回的重复抽样检查（bootstrap），并保持各标签原有细胞数。主配置请求 20 次重复；每次使用相应随机种子重新拟合。一次拟合产生有限关系矩阵即计为成功，达到最大训练轮数但没有触发提前停止并不会自动计为失败。

固定基因数为 `p` 时，`raw_predictions.csv` 必须保留全部 `p(p-1)` 条非自身有向关系。没有达到选择阈值的关系也保留并给出零频率或低分，方法不能只提交容易判断的关系来缩小评分范围。

主配置固定 `selection_threshold=0.0001`。因此一次成功拟合中，关系满足 `abs(effect) >= 1e-4` 时才计为“被选择”。这是预先固定的数值筛选线，不是统计显著性阈值，不对应 P 值，也不能单凭越过该线声称关系真实存在。

对每条 `source → target` 关系：

- `median_effect` 是所有成功重复、所有已提供细胞环境的关系强度中位数；
- `selection_frequency` 是关系绝对强度达到 `selection_threshold` 的“成功重复 × 细胞环境”观测比例；
- `direction_agreement` 是已达到阈值的观测中，占多数方向的比例；若从未达到阈值则为 0；
- `direction` 是 `median_effect` 的符号；
- `effect_k562`、`effect_rpe1` 等列分别保存每个环境跨成功重复的中位关系强度。

排名分数在查看最终检验结果前固定为：

```text
score = |median_effect| * selection_frequency * direction_agreement
```

`context_consistency` 比较各环境中位关系强度的方向是否一致，只纳入绝对强度达到阈值的环境。它是补充描述，不进入上述分数，也不会触发暂不判断。

暂不判断（abstention）按来源基因统一标记。出现下列任一情况时，同一来源基因指向所有目标的关系都标为暂不判断：

1. 成功重复比例低于 `bootstrap_success_fraction`；主配置阈值为 0.8，即 20 次中至少需要 16 次成功；
2. 该来源基因在各环境对照细胞中的平均总体方差低于 `minimum_source_variance`；主配置为 `1e-8`。

暂不判断的关系仍保留原始分数供复查，但排序时位于可判断关系之后。`coverage` 表示未被暂不判断的来源基因比例。它不是准确率，也不能用较高覆盖率代替正式评分。

## 细胞环境内部与跨环境运行的含义

运行入口只接受一组语义完整且处于同一阶段的公开文件：

| 运行方式 | 允许输入 | 能说明什么 |
|---|---|---|
| 环境内部 `within` | K562、RPE1 中的一个或两个环境；联合输入时必须同为 `train`、`tune` 或 `refit` | 在相同公开阶段内学习一个或两个环境的关系 |
| 跨环境 `cross` | 同一方向、同一阶段的一份 `source_*` 和一份 `target_adapt_*` | 用来源环境干预数据学习，并只用目标环境未干预对照适配环境差异 |

跨环境运行必须成对提供来源文件和目标适配文件。例如 K562→RPE1 的 `source_refit.npz` 可含 K562 公开学习与参数调节干预，RPE1 的 `target_adapt_refit.npz` 只能含 `non-targeting` 对照。RPE1 干预细胞和独立对照继续封存在最终检验区。RPE1→K562 使用对称规则。

这里的“适配”表示来源环境与目标对照共同参与共享关系和环境调整的联合拟合，不表示已经消除了批次、培养条件或细胞系之间的所有差异。一个跨环境方向通过，也不能掩盖另一个方向失败。

## 外部知识的使用边界

主分析配置 `configs/hypersca_c_v1.json` 固定 `prior_discount=0.0`，运行入口拒绝非零值。因此主结果不读取外部调控关系，也不会因已知关系获得较低的稀疏惩罚。

知识增强只属于 `prior_on_secondary` 次要消融。该消融把 `prior_discount` 设为 0.5，即对已登记先验关系使用原来一半的共享关系稀疏惩罚；它不会把先验关系固定为存在。当前 `configs/hypersca_c_prior_trust_v1.json` 的可信清单为空，所以在没有合格资产时必须记录 `official_assets_unavailable` 和 `no_nonoverlapping_preregistered_prior`，不能临时选一份知识库继续运行。

未来启用外部先验前，必须同时满足：来源和许可明确；关系文件与来源清单均有 SHA-256 内容指纹；有向关系集合指纹一致；来源清单声明不复用评分关系；项目维护方另行完成与任务 C 的 pooled 评分关系和 ChIP 方向参考关系的精确交集审计，并把交集为零的审计结果连同全部指纹事先写入独立的项目级可信登记表。来源方自述或来源清单中的独立性声明不能代替该可信登记和精确审计。任务 C 的 pooled 或 ChIP 评分关系不得转作模型先验，也不得在看过最终评分后选择先验。

## 八项预先登记的消融比较

消融是把某一组成部分去掉或改变，再在相同数据来源、划分、基因范围和评分规则下比较。每项可以按照预先登记内容改变实际使用的数据或模型组成；因此解释时必须把这些伴随变化一并考虑。当前登记顺序和设置固定如下；任何不利结果都必须保留。

| 登记项 | 实际变化 | 科研问题 | 什么结果才提供支持 |
|---|---|---|---|
| `primary` | 完整联合模型；不使用外部先验 | 作为其他七项的预先固定参照 | 它本身不能证明创新，只提供成对比较锚点 |
| `shared_only` | `enable_context_adjustments=false` | 环境特有调整是否提供额外信息 | `primary` 在预定跨环境和环境内指标上稳定优于本项，且覆盖率、失败和零效应检查没有恶化，才支持环境调整有贡献 |
| `separate_contexts` | 每个环境分别拟合，再按同一规则汇总 | 共享学习是否优于互不共享的独立模型 | `primary` 对本项的五随机种子配对改善区间支持正向改善，才支持共享关系有贡献 |
| `observational_only` | 删除干预细胞，只保留 `non-targeting` 对照细胞；样本数和样本组成也随之改变 | 整组干预数据是否增加信息 | `primary` 稳定优于本项，才支持整组干预数据有贡献；该差异不能单独归因于“干预标签”或某个算法组成，只看一条高分关系也不够 |
| `no_stability_weighting` | `bootstrap_repeats=1` | 跨重复的选择比例和方向一致性是否提高可靠性 | `primary` 在配对评分、随机种子稳定性和零效应检查上优于本项，才支持重复稳定性加权有贡献 |
| `acyclicity_off` | `acyclicity_weight=0.0` | 默认无环软限制是否有帮助 | 默认设置优于关闭设置且没有以降低覆盖率换取改善，才支持该限制；仍不能说明真实网络无反馈 |
| `acyclicity_strong` | `acyclicity_weight=0.1`，为默认值的 10 倍 | 结果是否对无环限制强度过度敏感 | 默认设置在预定指标和失败率上具有可解释优势，才支持当前强度；若结论随强度反转，应报告敏感性而不是挑选有利设置 |
| `prior_on_secondary` | `prior_discount=0.5`，仅接收独立登记先验 | 独立外部知识能否作为次要补充 | 只有合格先验通过独立审计且次要结果成对改善，才可称为知识增强；不能提高无先验主结果的证据等级 |

候选贡献应按下面的组合证据判断：

- “共享关系与环境特有调整的联合学习”至少需要 `primary` 同时优于 `shared_only` 和 `separate_contexts`，并在两个跨环境方向都保留改善；
- “只用目标环境未干预细胞进行适配”在现有八项中没有专门的“取消目标适配”对照。跨环境成绩只能说明整套做法的表现；若要把增益归因于目标对照适配，还需要另行预先登记直接对照；
- “稳定性和暂不判断提高可靠性”需要 `no_stability_weighting`、覆盖率、失败记录、五随机种子一致性和两类零效应检查共同支持。当前消融没有单独移除暂不判断规则，因此不能只凭该表声称暂不判断本身带来增益；
- “预先登记并完整保留消融”提高结果的可复查性，但不是算法性能创新。

所有消融输出当前都标记为 `claim_level=ablation_raw_inference_only` 和 `formal_score_status=not_sealed`。在封存评分和配对区间完成前，消融表只能用于检查运行和提出待检验解释。

## 与现有方法比较时的表述

DCDI、NOTEARS、SparseRC 等已经研究了相邻的结构学习或干预关系问题，因此“使用干预标记学习有向结构”本身不能作为 HyperSCA-C 的新颖性主张。NOTEARS 还提供了本版采用的无环软限制背景。它们在这里是研究背景和后续比较对象，不是已经完成的优劣结论。

只有全部方法使用相同数据、固定基因、数据划分、参数尝试机会和评分范围，并完成预先规定的配对比较后，才能表述 HyperSCA-C 相对某个具体方法的结果。在此之前不得使用“领先”“优于现有方法”“更准确”或“已证明算法创新”等措辞。若消融不支持候选贡献，应把 HyperSCA-C 定位为规范实现或可复查评测框架，并如实保留结果。

## 输出文件和当前证据等级

主运行产生四个可复查的分析输出文件（artifacts）：

| 文件 | 研究含义 |
|---|---|
| `raw_predictions.csv` | 固定基因集合中的完整非自身候选关系、原始强度、稳定性分量和暂不判断状态 |
| `fit_summary.json` | 请求与成功重复数、失败摘要、覆盖率、暂不判断比例和分数公式 |
| `method_status.json` | 本次运行是否完成原始推断、失败是否完整可见，以及结果是否具备进入后续排序的最低条件 |
| `run_manifest.json` | 输入、设置、代码状态、时间、设备和输出内容指纹的分析记录清单 |

主运行的 `status=completed_raw_inference` 和 `claim_level=raw_inference_only` 只表示原始推断文件已生成并通过内部格式检查。`usable_for_ranking=true` 也只表示至少一次重复成功且至少一个来源未被暂不判断，不表示封存评分已通过。消融运行另有 `formal_score_status=not_sealed`，明确表示正式结果尚未封存。

这些输出可以称为“模型推断的候选有向关系”或“待外部检验的关系排序”。不能称为实验确认的因果关系、药物作用机制、有效治疗靶点、患者获益或临床疗效。任务 C 的计算评测即使通过，也不能替代空间任务 S、药物任务 D、湿实验或临床验证。

## 已知限制和资源边界

1. **线性假设。** 当前模型只表示同时测量表达之间的线性预测关系，不能充分表示阈值效应、饱和、组合调控、时间延迟和非线性反馈。
2. **无环假设只是软限制。** 输出可能仍含循环；即使数值上近似无环，也不能据此断言真实生物网络无反馈。
3. **细胞系和批次差异。** 当前环境标签只有 K562 和 RPE1。模型没有显式的供体、实验批次、细胞周期或培养条件校正项；环境调整可能同时吸收生物差异和技术差异。
4. **跨环境适配的识别范围有限。** 目标环境只开放对照细胞，减少了干预响应泄漏，但不能保证共享关系与环境差异可以唯一分开，也不能排除未测混杂。
5. **RPE1 的方向参考并非 RPE1 特异。** 固定 CausalBench 分支为 RPE1 评分提供的 ChIP 方向参考实际来自 HepG2。该结果只能作为方向性补充，不能写成 RPE1 中的直接实验验证。
6. **参考关系和外部先验都不完整。** pooled 与 ChIP 关系只用于评分；未来先验还必须独立声明和审计。参考关系缺失不等于预测关系错误，参考关系存在也不等于当前细胞环境中的机制已确认。
7. **多次重复的审计粒度有限。** 当 `bootstrap_repeats>1` 时，当前正式文件保留成功次数和每次失败的紧凑原因，但不保存每次重复的完整矩阵、训练轨迹或提前停止状态。需要逐重复诊断时必须在正式运行前扩展记录规则，不能事后从汇总值还原。
8. **计算量随基因数快速增加。** 每个环境和每次重复都使用稠密 `p × p` 关系矩阵，并计算矩阵指数形式的无环限制；输出也有 `p(p-1)` 行。2 至 256 的核验上限用于限制这一成本，但尚不能代替真实预演的时间和显存测量。
9. **峰值资源尚未进入四个主输出。** 当前运行清单记录设备和持续时间，不记录峰值内存或峰值显存。全方法预演必须另行生成资源使用记录后，才能估计全量作业预算。
10. **并发运行需要分开目录。** 同一个输出目录不能由两个进程同时写入。程序会拒绝覆盖非空目录并核验已有结果，但这不等于跨进程锁；并发任务必须使用不同输出目录，并在汇总前核对运行身份。
11. **随机种子不保证跨设备逐位一致。** 运行会记录随机种子、CPU/GPU 设备、代码提交和代码状态指纹，但当前没有承诺不同硬件或不同 PyTorch 构建得到逐字节相同的浮点结果。

## 实测前检查表

- [ ] 数据来自固定 CausalBench 提交，许可、来源、细胞数、基因数和内容指纹均已复查。
- [ ] `public_manifest.json` 及其全部公开文件通过核验；没有打开或复制 `private/` 中的最终检验标签、细胞或文件。
- [ ] 五个共享划分仍使用随机种子 11、23、47、71、97，且同一干预基因没有跨越学习、参数调节和最终检验范围。
- [ ] 有序基因清单含 2 至 256 个不重复基因；选择依据只来自允许查看的学习数据，并在看评分参考关系之前固定。
- [ ] `within` 输入来自相同阶段；`cross` 输入是同一方向、同一阶段的完整来源—目标适配对，目标适配文件只含 `non-targeting`。
- [ ] 主配置与 `configs/hypersca_c_v1.json` 一致，特别是 `prior_discount=0.0`、`bootstrap_repeats=20` 和 `bootstrap_success_fraction=0.8`。
- [ ] 主配置保持 `selection_threshold=0.0001`；报告把它解释为 `abs(effect) >= 1e-4` 的数值筛选线，不写成统计显著性。
- [ ] 正式消融登记仍恰好包含八项固定顺序；可信先验登记为空时，预期 `prior_on_secondary` 明确报告资产不可用。
- [ ] 每个运行使用独立输出目录；磁盘、内存和显存预算已按 64 基因连接检查与 256 基因全方法预演实测，而不是仅凭估计。
- [ ] 预演只使用一个固定随机种子检查连接，不写成正式参数公平比较；正式结论保留全部五个随机种子和所有失败。
- [ ] 两类零效应检查、均值差简单对照方法（baseline）和预先登记的外部方法比较都已排入同一评分范围。

一次主运行的命令形式如下，路径必须替换为同一公开数据包内的实际文件：

```bash
python scripts/run_hypersca_c.py \
  --context k562=/path/to/public/within/k562/refit.npz \
  --context rpe1=/path/to/public/within/rpe1/refit.npz \
  --config configs/hypersca_c_v1.json \
  --gene-list /path/to/frozen_gene_list.json \
  --public-manifest /path/to/public/public_manifest.json \
  --output-dir /path/to/unique_output \
  --seed 11 \
  --device cuda
```

运行后还应核对：四个文件齐全且内容指纹一致；`requested_bootstraps`、`successful_bootstraps` 和所有失败原因完整；关系表恰有 `p(p-1)` 行且无非有限值；覆盖率和暂不判断原因按来源基因一致；运行身份中的输入、配置、基因清单、代码状态、设备和时间均可追溯。完成这些检查仍只代表分析流程可运行，不代表正式封存评测通过。
