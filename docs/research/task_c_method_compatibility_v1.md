# 任务 C 比较方法兼容性与证据边界 v1

## 这份说明解决什么问题

任务 C 比较的是：不同方法能否从同一批允许查看的单细胞数据中找回有向基因关系。方法依赖的软件、可用信息和返回形式不同，因此“程序能运行”不等于“比较公平”。本说明固定每种方法如何接入、哪些数据可以读取、哪些结果可以进入共同评分，并如实保留暂时不能运行的方法。

“全面比较清单”指预先登记的全部 19 种候选、简单对照、无效应对照和外部方法；“核心预演清单”是其中必须优先跑通的较小集合。外部方法失败时，其他方法可以继续运行，但失败方法仍保留在全面清单和最终报告中，不会因失败而被删除。

## 共同运行规则

统一命令是 `scripts/run_task_c_method.py`。它先核对方法登记、允许读取的数据、固定基因顺序和软件身份，再保存方法原始结果。只有原始结果满足三列 `source,target,score`、基因名属于固定清单、分数有限且非负时，才会生成共同关系表 `predictions.csv`。

共同关系表包含固定基因集合内所有非自身的有向关系。方法没有返回的关系补为零分，并用 `returned_by_method=false` 标明。这是为了让评价范围一致，不表示方法明确判断该关系不存在。重复关系只保留最高分；标准表本身没有重复关系。

关系强弱必须有官方依据。固定版本中，只有 GRNBoost 的返回顺序可作为强弱顺序，因而按原顺序换成递减正分。其他 CausalBench 方法只提供未排序的关系集合，所有已返回关系并列为 1 分，不把容器位置解释成新的排名。PSGRN 按其官方返回顺序保存前 1,000 条关系。

每次成功运行保留：

- `raw_predictions.csv`：投影后的三列原始关系分数；
- `predictions.csv`：补齐后的共同关系表；
- `method_status.json`：成功、失败或暂无官方代码的真实状态；
- `environment_manifest.json`：登记表、输入、固定代码、软件环境和命令模板的 SHA-256 记录。
- `trial_parameters.json`：方法启动前固定的候选编号、候选参数、细胞背景、比较情形、数据阶段和输入指纹。无需调节的方法也保存空参数记录。

候选参数文件的内容和 SHA-256 会同时写入运行身份、环境记录和方法状态，不能在方法结束后补写。正式候选只能用公开 `train` 文件拟合；选择命令再用独立的公开 `tune` 细胞响应评价这些已经完成的预测，不能在同一批细胞上边拟合边评价。选择记录明确保存训练输入和调节输入的两组指纹，并要求两者不同。不同基因顺序、细胞背景、跨环境方向、随机种子或比较规模的结果不能混用。

选择命令输出 `selected_parameters` 和可复核的 `selection_record_sha256`。随后统一运行命令可用 `--selection-record` 把这份选择记录交给 `refit` 比较范围：它会核对方法、基因顺序、细胞背景、方向、规模、随机种子和选中参数，再把记录内容及其 SHA-256 写入重新拟合的运行身份。这样形成“train 拟合候选 → tune 选择设置 → refit 重新拟合”的完整证据链。

外部程序的进程状态和资源记录放在 `raw_runtime/`，避免覆盖统一命令自己的状态。HyperSCA-C 的完整原始输出先保存在 `raw_method_output/`，然后才投影出共同三列。统一命令最多处理 256 个基因；已有目录不会被覆盖。只有真实数据控制器完成封存评分和强制文件核验后，状态才可以升级为 `passed_real_rehearsal`；本命令本身绝不写入该状态。

统一状态还记录内层运行状态、失败发生在运行阶段还是标准化阶段，并带有不含自身字段时计算的内容 SHA-256。重新使用结果时，外层状态必须与 `raw_runtime/method_status.json` 一致：成功标准化要求内层已经完成原始推断；外部程序自身失败时，两层失败名称必须相同；内层成功但三列或 HyperSCA-C 四文件证据无效时，外层才记录为 `failed_invalid_output`。

## 允许读取的信息

“观察信息方法”只能读取标签为 `non-targeting` 的未干预细胞。登记为观察信息的方法包括 Random1000、GRNBoost、PC、GES、GSP、NOTEARS Linear 和 Sortnregress。

“部分干预信息方法”可以读取公开学习文件中的未干预细胞和已公开的干预细胞，但不能读取独立验证数据。登记为部分干预信息的方法包括 HyperSCA-C、均值差简单对照、GIES、IGSP、DCDI-G、DCDI-DSF、DCDFG-LIN、DCDFG-MLP 和 PSGRN。

正式运行必须同时提供 Task C 的完整公开文件清单，并核对所选文件已经登记、SHA-256 一致、没有符号链接或未登记的硬链接。合成数据只能显式标为 `synthetic_smoke`，意思是“仅检查分析流程能否运行”；它不能被当作真实数据证据。任何方法都不得读取名称或路径含 `private` 的独立验证文件。

## 正式比较范围文件

正式预演不直接把任意大小的公开学习文件交给各方法。先用 `materialize_task_c_profile_input` 生成一份可从公开父文件完整重算的“比较范围文件”，再把它和记录文件一起传给统一命令。记录格式固定为 `task_c_profile_subset_v1`。旧的公开三数组文件接口仍保留，便于兼容不超过 256 个基因的已有单环境调用；正式预演则统一使用比较范围文件。

预先固定两种规模：`connection` 最多 64 个基因、每个实际细胞背景最多 2,000 个细胞；`comprehensive` 最多 256 个基因、每个背景最多 20,000 个细胞。两者的选择种子都是 11。候选基因必须属于 K562/RPE1 的共同基因，并在两种背景的允许干预来源中都达到公开清单规定的最少细胞数。随后按两种背景对照细胞的总体方差（`ddof=0`）平均值从高到低选择；方差相同时按基因名排序。

基因候选只来自两种细胞背景都达到公开最少细胞数的允许干预来源，因此这里选出的基因同时也是可学习的来源基因，不额外加入只有表达、没有公开干预细胞的目标基因。基因确定后，只保留未定向干预对照和这些已选基因的干预细胞；`excluded`、环境特有干预和未选基因干预全部在抽样前删除，避免它们占用有限的细胞名额或为观察信息方法增加额外信息。记录文件保存被删除的原行号、数量和按标签汇总。

抽样先为未定向干预对照和每个已选来源基因分别预留公开清单规定的最少细胞数（当前为 5），其余名额才按固定比例和种子分配。若细胞上限容纳不了原计划的全部来源基因，则按同一方差排序从尾部缩减，并在 `dropped_due_to_cell_budget` 中记录；至少保留两个来源基因，否则明确停止。输出再次核对对照和每个已选来源都达到最少细胞数。因此，不同方法看到的是同一批基因和同一批细胞，而不是仅仅拥有相同的数量上限。

单环境文件含表达、干预标签和基因名三个数组。跨环境文件另含环境标签；根据阶段分别来自同一方向的 `source_train/source_tune/source_refit.npz` 与相应的 `target_adapt_train/target_adapt_tune/target_adapt_refit.npz`。完成细胞和基因选择后，每个环境分别用至少两个未定向干预对照细胞计算均值和总体标准差，并按 `(表达值-对照均值)/对照标准差` 换算；标准差不大于 `1e-6` 时按 1 处理。变换名称固定为 `per_environment_control_zscore_then_row_concatenate_v1`，旧的“只减均值”名称不再接受。

记录文件保存所用规模、上限、种子、选择规则、公开父文件及其 SHA-256、基因名和原列号、每层干预在各自父文件中的行号、环境次序、输出数组摘要和输出文件 SHA-256。`train`、`tune` 与 `refit` 三个阶段使用同一个由公开 refit 对照父文件确定的基因顺序；训练和调节响应都只投影这份既定清单，不参与挑选基因。三阶段的实际细胞分别来自各自登记的父文件，父路径、父指纹和输出指纹必须分开。由于公开 NPZ 不保存原始全集行号，记录中的行号只解释为“在已注明父文件中的行号”，不会伪装成原始全集位置。核验程序会从公开父文件重新执行选择与换算，并逐数组比较。父文件、阶段、方向、行号、环境标签、基因顺序或输出内容任一项变化都会停止运行。该接口只接受登记的公开学习数据，不接受合成数据，也不读取独立验证数据。

HyperSCA-C 也通过 `--profile-input` 和 `--profile-manifest` 接收这份相同的比较范围文件。如果公开父文件超过细胞上限，它实际拟合的就是记录中的截取细胞，而不是完整父文件；运行清单同时记录比较范围文件、公开父文件、基因列号和细胞行号。原来的 `--context` 公开文件接口继续保留，供不采用正式比较范围的兼容调用使用。

核验完成后，统一命令把已核验的比较范围字节写入自己控制的临时文件，再交给外部工作进程或 HyperSCA-C；工作进程不会重新打开可能已被替换的原路径。运行结束前，公开清单、父文件和原比较范围记录还会再次核对。HyperSCA-C 的嵌套记录只用比较范围内容指纹、来源记录指纹和固定占位文字 `<verified-profile-input>` 表示实际核验输入，不接受调用者另传一个“身份路径”，也不会把随机临时目录冒充原始路径。统一命令自己的记录仍保存原比较范围内容和来源身份。

## CausalBench 方法

CausalBench 官方仓库固定为 <https://github.com/causalbench/causalbench>，提交固定为 `1a2143cffdc85f835b41ce8d52034be1bf903e71`，隔离环境名为 `hypersca-task-c-causalbench`。

当前接入的方法为 Random1000、GRNBoost、PC、GES、GIES、GSP、IGSP、NOTEARS Linear、DCDI-G、DCDI-DSF、DCDFG-LIN、DCDFG-MLP 和 Sortnregress。统一命令把登记的方法名称、允许的信息类型和关系返回含义原样传给固定工作进程，不在主环境中重新实现这些方法。

Varsortability 在该固定提交中是“数据中的方差顺序可能帮助方向判断”的诊断概念；实际可以运行的网络估计器是 `Sortnregress`。登记表只运行 Sortnregress，不把同一实现再以 Varsortability 名义计为第二种独立方法。

## 如何解释失败与可靠性

`completed_standardized_output` 只表示该次原始结果通过格式、基因范围和数值核验，并成功补齐到共同关系范围；它不表示生物学结论已经得到验证。超时、资源不足、软件不兼容、输出无效和官方资产缺失分别记录，不互相替代。

重新使用已有结果时，不只核对文件 SHA-256。均值差简单对照还会根据固定输入重新计算，以确认数值仍符合“干预组平均表达减去未定向干预对照组平均表达，再取绝对值”的规则；共同关系表也会从原始三列重新生成并逐项比较。HyperSCA-C 先用调用者实际提供的设置、基因清单、公开清单、细胞背景或比较范围文件重建身份，再以相同种子和输入在临时目录确定性重跑，逐字节比较原始关系表、拟合摘要和方法状态。这样，即使有人同步改写预测和所有清单校验值，结果也不能作为原运行复用。这些检查提高可复查性，但仍不能把不完整参考网络解释成完整因果真值。

运行身份逐文件记录统一入口、比较范围生成与核验、标准化、公开数据核验、运行监督、方法登记、HyperSCA-C 模型及稳定性核验、两个外部工作进程等固定代码闭包。HyperSCA-C 设置和基因清单、外部隔离环境记录及官方源码状态作为对应方法的附加输入单独记录。外部方法在启动前用有时间上限的 `conda list` 读取当前包清单，与准备阶段记录逐项比较，并把规范化后的内容指纹纳入运行身份；方法结束后和复用结果时还会再次读取。当前环境和准备记录不同，或运行期间发生变化，都会停止复用或发布。任一固定依赖在运行后或复用前变化，已有结果都不能复用。
