# HyperSCA v0.6.0

Release date: 2026-08-12

## Summary

HyperSCA v0.6.0 fixes a reviewed, evidence-gated baseline after the integration of PRs #1-#5. Those changes established trusted communication and behavior sidecars, compact benchmark reporting, admission/from-scratch guardrails, and unified spatial-annotation gates. This release also publishes the 2026-08-10 causal-inference and spatial drug-mechanism landscape assessment together with its selected Bear evidence artifacts.

The release is intentionally conservative. HyperSCA remains an audit-stage research prototype. The hyperbolic v3 and celcomen-inspired energy modules remain `audit_only_no_promotion`; target-rank delta is still zero, and no algorithm-superiority or externally validated spatial drug-mechanism claim is made.

## Branch Consolidation

- `main` is the sole public development and release line after v0.6.0.
- PRs #1-#5 were already merged into `main` before this release branch was created.
- The only commit unique to the remote `crc-icb-from-scratch-local` branch is patch-equivalent to the benchmark documentation already present on `main`.
- Uncommitted experimental modules from the local source workspace are not included. They remain a local migration source and must enter future releases through narrow PRs from a clean `main`.
- The legacy remote branch may be deleted only after the tag and GitHub Release have been verified.

## Known Limitations and Next Priorities

1. Add an editable-install package contract and Python 3.10 CPU CI so default `pytest` no longer depends on `PYTHONPATH=.`.
2. Wire the evidence-gated target-ranking policy and reproducible causal null controls through separate PRs.
3. Freeze the Task C/S/D benchmark artifact contract and simple baselines.
4. Validate Task C on CausalBench before making Task S own/neighbor propagation the first core spatial milestone.
5. Compare complex spatial-counterfactual models only after external splits, nulls, calibration, and compute reporting are fixed.

Problems discovered after publication must be corrected in a new patch release. The `v0.6.0` tag must not be moved.
