# HyperSCA 任务 C 真实数据预演设计

日期：2026-08-12

状态：已确认，待实施计划

分支：`design/real-data-readiness`

## 1. 目的

本设计为 HyperSCA 建立第一个可复查的真实干预评测闭环。首轮只处理任务 C：利用部分单细胞基因干预数据学习有向基因关系，并检验模型能否推广到未见干预和另一个细胞环境。

首轮使用 CausalBench 的 K562 和 RPE1 数据，全面比较主要公开方法。交付终点是完成真实数据预演、方法可用性检查和全量运行资源评估，不自动启动全部正式作业。

本设计延续以下已冻结原则：

- 所有方法使用相同数据、基因、划分和参数尝试上限；
- 主要指标在查看结果前固定；
- 简单对照方法、零效应检查、覆盖率和失败案例必须报告；
- 任务 C 的通过不能替代空间任务 S 或药物任务 D 的证据；
- 结果最多支持“基准支持的候选方法”，不支持临床疗效、靶点有效性或普适算法优势。

## 2. 当前项目基础与缺口

设计开始时，最新 `origin/main` 为 `5194ec5`，完整测试结果为 `270 passed`。

项目已有：

- Python 3.10 可复现环境；
- 任务 C/S/D 的固定比较规则；
- 因果结果的零效应检查和证据门控；

- 面向使用者的通俗术语规则。

仍缺少：

- 可复现的细胞系内部干预划分和双向外部检验；
- 与任务 C 科学对象一致的 HyperSCA 候选方法；
- 主要公开方法的隔离运行和统一结果转换；
- 多随机种子汇总、置信区间、零效应检查和正式准入判断；
- 真实数据预演、资源评估和全量作业清单。

## 3. 关键科学边界

当前 HyperSCA 阶段 2 推断的是细胞群之间的通讯关系。其变量是细胞群，并将基因作为探索性重复观测。CausalBench 评估的是基因对基因的有向关系，其变量是基因、观测是细胞。

两者不能直接比较。现有阶段 2 结果不得通过格式转换冒充任务 C 的基因网络。任务 C 将新增专用方法 **HyperSCA-C**，现有细胞群通讯流程保持不变。

“带干预标记的结构方程”已有 DCDI、NOTEARS、SparseRC 等邻近工作。因此，HyperSCA-C 的候选贡献限定为：

1. 联合学习两个细胞环境的共享关系和环境特有调整；
2. 只使用目标环境未干预细胞完成外部适配；
3. 把重复稳定性、跨环境一致性和暂不判断纳入正式结果；
4. 用预先固定的消融比较检验上述组成部分是否真正有贡献。

若消融结果不支持这些贡献，项目应将 HyperSCA-C 定位为规范实现或评测框架，不宣称新算法。

## 4. HyperSCA-C 方法定义

### 4.1 输入

每次运行接收：

- 细胞乘基因表达矩阵；
- 每个细胞的干预基因或未干预标签；
- K562 或 RPE1 环境标签；
- 固定的学习、参数调节和封存检验标记；
- 固定基因顺序和输入文件内容指纹。

主要版本不读取外部调控数据库。知识增强版只能作为独立的次要分析，并与无知识版本成对报告。

### 4.2 共享关系与环境差异

对环境 `c`，关系矩阵写为：

```text
A_c = A_shared + Delta_c
```

- `A_shared` 表示 K562 与 RPE1 可共享的关系；
- `Delta_c` 表示该环境的有限调整；
- 对角线固定为零，不允许基因把自己作为直接上游关系。

跨环境检验时，来源环境的干预数据用于学习共享关系；目标环境只提供未干预细胞，用于估计有限的环境调整。目标环境的干预细胞始终封存到最终评分。

### 4.3 干预标记

当一个细胞中的基因 `g` 被直接干预时，模型不计算 `g` 自身的表达解释误差；其他基因的变化仍参与学习。这样，干预信息主要帮助判断 `g` 指向哪些下游基因，而不是让模型学习实验操作本身。

未干预细胞的所有合格基因参与表达关系学习。

### 4.4 第一版模型范围

第一版采用可检查的线性结构方程，并包括：

- 对异常表达较稳健的预测误差；
- 对关系数量的限制；
- 对环境特有调整幅度的限制；
- 对无法稳定解释的循环关系的软限制；
- 学习集内部的重复抽样。

循环限制是建模假设，不代表真实基因网络没有反馈。必须报告该假设，并把关闭或加强循环限制作为预先登记的消融比较。非线性版本不属于本轮交付范围。

### 4.5 关系分数与暂不判断

每个来源基因—目标基因关系输出：

- 有向作用强度；
- 正向或负向作用；
- 重复抽样中被选择的比例；
- 重复抽样中的方向一致性；
- K562 与 RPE1 的一致性；
- 是否暂不判断及原因。

主要排名分数在查看封存结果前固定为：

```text
score = |重复拟合关系强度的中位数|
        * 被选择的重复拟合比例
        * 被选择后方向一致的比例
```

“被选择”表示关系在已经由学习集和参数调节集确定的稀疏限制下非零。若从未被选择，分数为零。该公式、稀疏限制和重复次数写入共享配置，正式检验时不得变更。同一来源基因的全部目标关系必须形成完整、有限、无重复的分数表。

暂不判断按来源基因统计。若该来源不在固定基因集合、允许查看的未干预细胞中没有表达变化、少于 80% 的重复拟合成功，或整个响应轮廓无法得到有限分数，则该来源的关系标记为暂不判断。评估程序独立判断某个来源是否有足够的封存干预细胞；这个数量不能反馈给方法。覆盖率沿用现有任务 C 定义，按可评分的合格来源基因比例计算，避免把大量低分非关系误记为拒绝判断。

### 5.2 存放规则

### 5.3 核验记录

每个数据集必须保存：

- 下载地址、下载时间和许可；
- 官方代码提交版本；
- 原始文件和统一输入文件的 SHA-256；
- 细胞数、基因数、未干预细胞数；

任一关键指纹不匹配时停止运行，不自动重建后继续使用旧结果。

## 6. 固定数据划分

### 6.1 细胞系内部检验

先在两个细胞系共同可测、且有合格干预的来源基因中生成一份共享划分，再对 K562 和 RPE1 分别执行：

- 60% 合格干预基因用于学习；
- 20% 用于参数调节；
- 20% 保持封存，只用于最终检验。

按被干预基因整体划分。同一干预基因的细胞不得跨越学习、调节和检验集合。

同一个来源基因在 K562 和 RPE1 中使用相同划分。若某个基因属于封存检验集合，则两个细胞系的该基因干预细胞都不得进入学习或参数调节。这保证“未见干预”表示模型在任何细胞系都没有见过该基因的干预响应。仅在一个细胞系合格的来源基因不进入主要内部比较，可作为单独的环境特异补充结果。

未干预细胞也按学习、调节和检验用途独立划分。参数确定后，可在不打开最终检验集的前提下，用学习集和调节集重新拟合。最终仍有 20% 未见干预基因和独立未干预细胞用于评分。

### 6.2 双向外部检验

K562→RPE1：

- K562 未干预和干预数据用于学习与调节；
- RPE1 只开放一部分未干预细胞用于环境适配；
- RPE1 的干预细胞和独立未干预细胞全部用于最终评分。

RPE1→K562 使用完全对称的规则。

双向结果分别报告。一个方向通过不能掩盖另一个方向失败。

### 6.3 不使用干预的辅助比较

辅助训练方式只使用被允许的未干预细胞。它用于判断各方法是否真正从干预信息受益，不替代部分干预的主要比较。

### 6.4 随机种子和基因集合

- 正式随机种子固定为 `11、23、47、71、97`；
- 基因筛选只使用学习阶段允许查看的未干预细胞；
- 跨环境比较使用 K562/RPE1 共同可测的固定基因集合；
- 所有方法接收相同基因、细胞、干预划分和评分范围；
- 检验结果、参考关系和封存干预响应不得影响基因筛选。

## 8. 统一运行流程

```text
官方数据
  -> 来源和内容核验
  -> 固定划分与封存记录
  -> HyperSCA-C 和外部方法独立运行
  -> 统一关系结果表
  -> 同一评分规则
  -> 零效应检查与证据等级判断
```

### 8.1 方法连接边界

每个方法只需实现统一的输入和输出边界：

输入：表达矩阵、干预标签、基因名、环境、允许的数据范围和随机种子。

输出：来源基因、目标基因、方向、分数，以及可选的作用值和暂不判断原因。

外部方法不得直接写入最终汇总。其原始结果先保存，再由独立转换步骤生成统一关系表。

统一关系表覆盖固定基因集合中的全部非自我有向关系。若方法只返回前若干条关系，未返回关系记为零分；若方法无法判断没有见过干预的来源基因，这些关系同样记为零分并标记来源暂不判断。零分并列关系按固定基因名顺序处理。任何方法都不得通过只提交容易预测的关系来缩小自己的评分范围。

### 8.2 运行身份

每次运行身份至少包含：

- 数据集和环境；
- 数据划分标识；
- 学习方式；
- 方法和方法版本；
- 参数配置摘要；
- 随机种子；
- 代码提交；
- 输入文件指纹；
- 比较规则指纹。

同一身份不得静默覆盖。恢复运行前重新核对输入指纹和已有文件完整性。

## 9. 评分和结论规则

### 9.1 主要指标

沿用 `configs/benchmark_contract_v1.json`：

- 主要指标：average precision；
- 方向：越高越好；
- 参考关系只参与评估，不参与学习、基因筛选或参数选择。

主要指标在所有方法共用的完整有向关系范围上计算。方法自身的覆盖率和暂不判断比例另外报告，不通过删除未判断关系改变主要指标。

### 9.2 次要与补充指标

现有次要指标：

- AUROC；
- precision at 1,000 和 5,000；
- 有向关系方向正确率；
- 覆盖率；
- 暂不判断比例。

额外报告 CausalBench 官方的干预分布变化和漏检相关指标。这些是补充结果，不改变已冻结主要指标，也不能用来掩盖主要指标失败。

### 9.3 不确定性

- 使用五个固定随机种子；
- 采用 95% 配对分组重复抽样区间；
- 保留所有失败随机种子；
- 报告逐环境、逐方向和汇总结果，不只报告最佳运行。

### 9.4 进入下一证据阶段

任务 C 只有同时满足下列条件，才可标记为 `benchmark_supported_candidate`：

1. 覆盖率不低于 0.80，暂不判断比例不高于 0.20；
2. 至少 4/5 个固定随机种子成功；
3. K562↔RPE1 双向外部检验按预定规则通过；
4. 两类零效应检查通过；
5. 与均值变化方法使用相同数据、基因、划分和参数机会；
6. 相对均值变化方法的主要指标配对改善 95% 区间下界严格大于 0。

超过简单参照只支持进入下一证据阶段。若要表述“优于某外部方法”，必须对该方法进行单独配对比较，并报告其区间和失败情况。

## 10. 零效应检查和消融比较

### 10.1 强制零效应检查

1. 在同一环境内打乱干预标签，同时保持各组细胞数；
2. 从未干预细胞中重复抽取假干预组。

真实结果必须优于零效应结果。打乱标签后不得持续出现与真实运行相当的高置信关系。

正式运行前，在共享配置中固定零效应重复次数和通过阈值。阈值只能根据模拟数据和参数调节集确定，不能根据封存检验结果反推。

### 10.2 HyperSCA-C 强制消融

- 只学习共享关系，不学习环境特有调整；
- 不共享环境，只分别学习；
- 不使用干预信息；
- 不使用重复稳定性修正；
- 关闭或加强循环限制；
- 无外部知识与知识增强版本成对比较。

消融结果用于解释性能来源，不根据最终结果删除不利消融。

## 11. 运行记录和失败处理

### 11.1 现有强制文件

每次运行继续生成：

- `run_manifest.json`；
- `input_summary.json`；
- `metrics.json`；
- `predictions.csv`；
- `promotion_decision.json`。

### 11.2 新增记录

- `split_manifest.json`：固定分组和泄漏检查；
- `method_status.json`：完成、失败、超时或不可用状态；
- `resource_usage.json`：时间、内存、显卡和磁盘；
- `environment_manifest.json`：外部方法来源、版本和环境；
- `null_control_metrics.json`：零效应检查结果。

### 11.3 失败规则

- 文件指纹不符、划分泄漏、标签缺失或无效数值：立即停止；
- 单个外部方法失败：记录后继续其他方法；
- 缺少任一强制文件：该运行失败；
- 只有预演结果：保持 `workflow_validation_only`；
- 部分完成的结果不得进入正式汇总；
- 方法失败、超时和内存不足不得从比较分母中静默删除。

每个外部方法在预演结束时必须得到以下状态之一：

- `passed_real_rehearsal`；
- `official_code_incompatible`；
- `official_assets_unavailable`；
- `failed_timeout`；
- `failed_resource_limit`；
- `failed_invalid_output`。

不允许保留“未尝试”状态。

## 14. 代码组织方向

实施计划应把可复用逻辑放在 `src/`，把参数读取和命令入口放在 `scripts/`。建议按职责拆分：

- 官方数据准备与来源记录；
- 固定划分与泄漏检查；
- HyperSCA-C 模型；
- 外部方法登记和统一转换；

## 15. 测试设计

### 15.1 基础测试

- 干预基因自身误差被正确排除；
- 共享关系和环境特有调整可恢复；
- 自我关系始终为零；
- 分数有限、方向正确、排序可复现；
- 来源级覆盖率和暂不判断计算正确。

### 15.2 泄漏测试

人为混入以下信息时必须失败：

- 封存干预标签；
- 最终检验细胞；
- 参考关系；
- 根据检验结果选择的基因；
- 与记录不一致的数据划分。

### 15.3 小型模拟闭环

- 使用已知有向关系生成未干预和干预细胞；
- 检查主要方向恢复；
- 检查打乱标签和假干预后结果下降；
- 检查跨环境共享和环境差异可分开报告。

### 15.4 外部方法连接测试

- 每个方法输入范围与固定划分一致；
- 原始结果可转换为统一关系表；
- 超时、失败和缺失文件按规则记录；
- 独立环境版本进入运行记录。

### 15.5 项目回归测试

实施完成后运行完整 `pytest`，并单独运行任务 C、比较规则、零效应检查和通俗术语检查。空间分析、靶点发现和现有因果流程不得因任务 C 扩展而退化。
